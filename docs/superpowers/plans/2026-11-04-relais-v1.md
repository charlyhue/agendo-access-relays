# Relais Agendo Access V1 : plan d'implémentation

> **Pour les agents :** sous-skill requis : superpowers:executing-plans (exécution native, une
> tâche après l'autre). Les étapes sont des cases à cocher (`- [ ]`).

**But :** livrer `relay-sni` et `relay-push` (chantier D de la spec), avec tests, fuzzing,
images Docker, CI et guide de déploiement Dokploy.

**Architecture :** un workspace Rust (tokio) de trois crates. `relay-common` regroupe la
configuration par variables d'environnement, les logs JSON, les métriques, les limites par IP et
l'arrêt propre. `relay-sni` contient les décodeurs (PROXY v2, ClientHello), la poignée de main,
le multiplexeur et les deux ports. `relay-push` contient l'API HTTP (axum), les quotas en
mémoire et les clients APNs et FCM (reqwest, rustls). Chaque binaire expose une fonction
`run`/`serve` qui prend des écouteurs déjà liés : les tests d'intégration lancent le vrai
serveur sur des ports éphémères, contre une fausse maison et un faux APNs/FCM.

**Pile :** Rust 2024 (MSRV 1.90), tokio, bytes, tracing + tracing-subscriber (JSON), axum,
reqwest (rustls, webpki-roots), p256 (ES256), ring (RS256), `agendo-access-protocol` (Git,
option `codec`), cargo-fuzz, cargo-chef, musl, image `scratch`.

**Spec :** `docs/superpowers/specs/2026-11-04-agendo-access-design.md` du dépôt agendo, branche
`agendo-access` (sections Relais, Protocole commun, Configuration Traefik, Sécurité,
Découpage). Le crate `agendo-access-protocol` (même branche) en est la référence exacte.

## Contraintes globales

- Dépendance : `agendo-access-protocol`, dépendance Git du dépôt du socle (au départ sur sa
  branche de développement, aujourd'hui au tag `v0.42.0`, voir `docs/deploy-dokploy.md`).
  On ne modifie jamais le dépôt agendo.
- Français partout : logs, commentaires, docs, erreurs.
- Aucun secret dans le code, Git, `.env`, logs. Clé APNs et compte FCM : fichiers montés
  (chemins par variables). Le relais SNI n'a aucun secret et n'ouvre aucune connexion sortante.
- Aucun domaine ni seuil en dur : variables d'environnement, valeurs par défaut documentées.
- Aucun `unwrap`/`expect` sur une donnée réseau. Chaque lecture est bornée en taille et en
  temps. Connexions limitées par IP et au total.
- Valeurs du protocole (crate) : en-tête de trame 9 octets, charge ≤ 64 Kio, fenêtre initiale
  256 Kio, crédit cumulé ≤ 16 Mio, crédit rendu par moitié de fenêtre, ping 25 s, coupure après
  3 pings sans réponse, poignée de main en 10 s, 1 024 flux par tunnel, `GOAWAY` 0 arrêt,
  1 remplacé, 2 auth refusée, 3 faute de protocole, 4 jeton expiré, 5 aucune version commune.
  `CLOSE` 0 normal, 1 refusé, 2 erreur, 3 fenêtre dépassée, 4 délai.
- Push : statuts `sent | unregistered | rejected | quota`. Alerte en clair
  `GENERIC_ALERT`, `mutable-content: 1`, `interruption-level`, `apns-collapse-id`, enveloppe
  sous `agendo`, `sound.critical = 1` pour `critical`. FCM : données `agendo_key_id`,
  `agendo_ciphertext`. APNs 410 et FCM `UNREGISTERED` donnent `unregistered`.
- Images : `ghcr.io/charlyhue/agendo-relay-sni`, `ghcr.io/charlyhue/agendo-relay-push`,
  étiquetées par SHA.
- Traefik de Dokploy : v3.7.16 (`TRAEFIK_VERSION` dans `packages/server/src/setup/traefik-setup.ts`),
  entrée `websecure`, résolveur `letsencrypt`. `proxyProtocol` se met dans
  `tcp.serversTransports` (forme `loadBalancer.proxyProtocol` dépréciée depuis 3.5.2).

## Points d'attention de la revue

1. ClientHello fragmenté sur plusieurs enregistrements TLS, ou envoyé octet par octet : il est
   réassemblé dans la limite de taille, et le délai coupe un client trop lent.
2. Une maison qui ne lit plus son tunnel : les autres tunnels continuent, la mémoire reste
   bornée (fenêtres), le ping manqué ou le délai d'écriture coupe le tunnel.
3. Une maison qui se reconnecte alors que l'ancien tunnel a des flux ouverts : l'ancien reçoit
   `GOAWAY` 1, les nouveaux flux vont au nouveau, et la fin de l'ancien ne désinscrit pas le
   nouveau.
4. Un client qui ferme pendant que la maison envoie encore : `CLOSE` émis, flux retiré, jauge
   des flux revenue à 0.
5. Un jeton de téléphone iOS qui contient des caractères de chemin (`../`, `?`, `#`) : refusé
   avant toute requête, jamais injecté dans l'URL APNs.

### Tâche 1 : workspace et `relay-common`

**Fichiers :** `Cargo.toml`,
`crates/relay-common/src/{lib,config,logs,metrics,limits,shutdown,time}.rs`.

**Interfaces produites :**
- `config::Env` : lecture de variables (`Env::from_os()`, `Env::from_pairs(&[(k, v)])` pour les
  tests) ; `required(&self, name) -> Result<String, ConfigError>`,
  `parse_or<T: FromStr>(&self, name, default: T) -> Result<T, ConfigError>`,
  `trusted_keys(&self, name) -> Result<TrustedKeys, ConfigError>`. `ConfigError` nomme la
  variable, jamais sa valeur.
- `logs::init(service: &'static str)` : JSON sur stdout, filtre `RELAY_LOG` (défaut `info`).
- `metrics::{Counter, Gauge, Registry}` : `Registry::counter(name, help, labels)`,
  `Registry::render() -> String` (format texte Prometheus) ;
  `metrics::serve(listener, registry, shutdown)` : `GET /metrics`, `GET /sante`.
- `limits::{IpLimiter, IpGuard}` : `IpLimiter::new(per_ip, total)`,
  `try_acquire(ip) -> Option<IpGuard>` ; IPv6 regroupé par /64 ; le garde libère au `Drop`.
- `shutdown::signal()` : future résolue sur SIGTERM ou Ctrl-C.
- `time::now_unix() -> i64`.

- [ ] Tests d'abord : `parse_or` refuse une valeur illisible en nommant la variable ;
  `trusted_keys` accepte `k1=…,k2=…` ; `IpLimiter` refuse au-delà de `per_ip` et du total,
  libère au `Drop`, compte deux IPv6 du même /64 ensemble ; `render` produit
  `# HELP`, `# TYPE` et les valeurs étiquetées.
- [ ] Implémenter, `cargo test -p relay-common`, clippy, commit.

### Tâche 2 : PROXY protocol v2 (`relay-sni/src/proxy_protocol.rs`)

`MAX_HEADER_LEN = 16 + 1024` ; `encode_v2(source, destination) -> Vec<u8>` (tests et fausse
maison). `read_header(stream, timeout) -> Result<(ProxyHeader, Vec<u8> /*surplus*/), ProxyError>`.

- [ ] Tests : en-tête v4 et v6 exacts, TLV ignorés, surplus rendu, signature fausse, version 1

  au-delà du maximum refusée dès l'en-tête, troncature octet par octet donne `Ok(None)`.
- [ ] Implémenter, tester, commit.

### Tâche 5 : `relay-sni`, configuration, registre, poignée de main

**Interfaces :**
- `config::SniConfig::from_env(&Env)` : `RELAY_SNI_ZONE` (requis), `RELAY_TRUSTED_KEYS`
  (requis), `RELAY_SNI_PROXY_PROTOCOL` (`required` par défaut | `off`), `RELAY_SNI_PROXY_FROM`
  (CIDR séparés par des virgules, requis si `required`), adresses `RELAY_SNI_PUBLIC_ADDR`
  (`0.0.0.0:8443`), `RELAY_SNI_TUNNEL_ADDR` (`0.0.0.0:9443`), `RELAY_METRICS_ADDR`
  (`127.0.0.1:9100`), limites (voir la doc de déploiement).
- `registry::Registry` : `register(host, TunnelHandle) -> Option<TunnelHandle /*remplacé*/>`,
  `get(host)`, `unregister(host, id)` (seulement si c'est encore le même tunnel).
- `tunnel::handshake(io, &SniConfig, now) -> Result<Accepted, HandshakeError>` : `HELLO` →
  `CHALLENGE` → `AUTH` (`verify_auth`) → `READY`, en 10 s ; `GOAWAY` 5, 2 ou 4 en cas de refus.

- [ ] Tests (fausse maison, `tests/support/`) : poignée de main acceptée ; versions sans
  intersection donnent `GOAWAY` 5 ; mauvaise signature du nonce, `kid` inconnu, hôte hors zone
  donnent `GOAWAY` 2 ; jeton expiré, `GOAWAY` 4 ; trame `DATA` avant `READY`, `GOAWAY` 3 ;
  silence, coupure après le délai.
- [ ] Implémenter, tester, commit.
